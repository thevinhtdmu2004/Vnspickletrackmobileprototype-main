# Support Runbook

## 1. Purpose

Defines how support requests should be handled after pilot or production deployment.

---

## 2. Support Channels

Possible channels:

```text
- Zalo group
- Phone call
- Email
- GitHub Issue for internal team
```

---

## 3. Support Categories

| Category | Examples |
|---|---|
| Login | Cannot login, forgot PIN |
| Attendance | Wrong status, cannot save attendance |
| Package | Wrong remaining sessions, renewal not reflected |
| Member | Wrong profile/phone/class |
| Report | Wrong report number, revenue visibility issue |
| Backup | Backup failed, export failed |
| Bug | App crash, UI issue |

---

## 4. Severity

| Severity | Meaning | Response |
|---|---|---|
| P0 | App unusable | Immediate escalation |
| P1 | Critical business rule or data issue | Same day |
| P2 | Important workflow issue | Planned fix |
| P3 | Minor UI/wording | Backlog |
| P4 | Enhancement | Product review |

---

## 5. Support Handling Steps

```text
1. Record requester and role.
2. Record affected screen/flow.
3. Capture screenshot if possible.
4. Classify severity.
5. Check if data correction is needed.
6. Create issue if development fix is required.
7. Confirm resolution with requester.
```

---

## 6. Required Information

```text
- User role: Admin / Coach / Member
- Device/app version
- Screen name
- Steps to reproduce
- Expected result
- Actual result
- Screenshot/video if available
```
